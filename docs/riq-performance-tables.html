1. RiQ vs Pro-Q 4 vs ReaEQ

RiQ 0.828, FabFilter Pro-Q 4 and ReaEQ (Cockos) on the same curves in REAPER 7.84 (Windows builds), 30 instances on one track, 60 s of noise, best of 3 renders; the range covers two separate runs. Cost is the share of one CPU core per instance in real time; lower is better. For scale, 0.01 % = 6 ms of CPU per minute of audio, and 100 such instances use 1 % of one core. Bold marks the lowest cost in the row; ratios below 1 mean RiQ is cheaper.

On a single bell ReaEQ is cheaper: it is built into REAPER, while every VST3 instance carries a fixed host overhead that is most of RiQ's cost there. From a few bands on, RiQ is the cheapest of the three.

2. Mixing loads

The same setup with a typical number of instances per session: 18 instances with 4 bells each (200 Hz −3 dB Q 1.5, 800 Hz +3 dB Q 1, 2.5 kHz −2 dB Q 2, 8 kHz +3 dB Q 0.7), and 24 instances with a high pass at 200 Hz and a low pass at 4.5 kHz, both 24 dB/oct. ReaEQ only has 12 dB/oct cuts, so it gets two of them in a row for each 24 dB/oct cut: the same slope and the same number of filters.

Compare plugins within a row, not rows with each other. The method (an offline render of the track, minus the same render without plugins) under-reports very cheap instances when there are fewer of them: run at the same 18 and 30 instances, RiQ with 4 bells measured 0.0046 % and 0.024 %, while 1 bell stayed at 0.006 %. Pro-Q 4 and ReaEQ move much less. Absolute numbers below about 0.01 % are close to the measurement floor.

3. Engine optimization

Native benchmark of the DSP engine alone (g++ -O3), one core of a Ryzen 9 5950X at 3.37 GHz, plugin window closed. RiQ 0.81 is the first release, before any optimization. Since then: bit-exact restructuring, SIMD (SSE2, and AVX2/FMA chosen at run time), state-space filter sections, a faster FFT for linear phase, and 64-bit processing straight from the host. The output differs from 0.81 by at most −126 dB with linear phase and −214 dB without it.
